### 1. 弄清面试四个接口是怎么"串"起来的

- create_interview → get_interview_info → get_next_question → submit_text_answer 不是后端接口互相调用，而是前端 Vue 当"总指挥"：onMounted 页面加载自动验证 token、按钮 @click 触发、提交答案成功的回调里自动连调 get_question 取下一题
- 触发方式三种：生命周期（onMounted）、用户事件（@click）、代码链式（一个请求的成功回调里再发下一个）
- 后端接口彼此独立无状态，靠 token + 数据库状态衔接；用 /docs 手动按序调用同样能走通全流程

### 2. 梳理现代 Web 架构版图

- 四代演进：单体（后端拼 HTML）→ 前后端分离（REST+SPA，本项目）→ 微服务+BFF（大厂）→ Serverless/BaaS（独立开发者）
- 本项目准确定位：前后端分离，"流程编排在前端、核心业务和状态在后端"——不是真"薄后端"（LLM 出题/评分/报告全在后端）

### 3. 接口调接口的边界

- 后端调外部服务接口（DashScope）= 标准做法，本项目即此；同进程接口之间 HTTP 互调 = 反模式，应直接 import 函数（本项目没犯）
- 判断标准一句话：同进程调函数，跨进程/跨机器才走 HTTP

### 4. SQLite 并发自测：两个请求同时查同一场面试会怎样

- 纯读并行安全（SHARED 锁可共享）；写写/读写才会撞锁，撞了默认等 5 秒，超时抛 database is locked → 500
- 项目没开 WAL/busy_timeout，但事务窗口极短（UPDATE→commit 只隔一条 SELECT），实际风险低；加固只需 timeout=30 + PRAGMA journal_mode=WAL 两行
- 意外发现：interview_api 的 async def 接口全跑在事件循环单线程上，彼此天然串行，反而不容易自己撞自己的锁

### 5. 查证：项目用的是朴素连接还是连接池

- 全项目走 db.py 的 get_db/return_db：每次 connect、用完 close，_connections 只是"登记簿"不是池
- db_pool.py（线程本地池）零引用，是死代码；SQLite 建连微秒级，朴素连接反而是合理选择（MySQL 建连几十毫秒才必须池化）

### 6. 系统学习 async/def 与 FastAPI 并发模型（本次大头）

- async 本质 = 换一种等待方式：await 把请求冻成内存存档（不占 CPU/线程），事件循环转身接待别人；等待期间真正干活的是"外面的世界"（DashScope 服务器/操作系统/后台线程），结果回来再解冻收尾
- 角色分工：事件循环=唯一秘书（asyncio，1 条线程）；线程池=40 工人（anyio 定的上限，按需雇佣）；FastAPI=分诊总管（async 自己跑 / def 丢线程池）；uvicorn=底层收发 HTTP
- 精确规则：async 里禁止同步阻塞等待。慢活两条合法路：await 异步库（httpx/AsyncOpenAI）或丢 def——本项目选 def（generate_questions、generate_evaluation 写对了）
- 项目现状：业务代码 100% 同步，async def 接口是"穿着 async 外衣的同步函数"，靠 FastAPI 分诊兜底；个人规模完全够用，换异步=全链路换血（httpx/AsyncOpenAI/aiosqlite）性价比低
- FastAPI "Fast" 真相：uvicorn/asyncio 引擎 + Rust 级 Pydantic 校验 + 类型注解免运行时猜测 + 无历史包袱；但本项目瓶颈 99.9% 在 LLM 等待，框架快慢无感——实际价值是 /docs 文档、参数校验、现代 Python 学习
- 高并发 ≠ 异步：三条路（多进程多线程/异步 IO/混合），异步只是 IO 密集场景性价比之王；大企业异步用来干"等"的事（等大模型、等微服务、撑长连接）

## 学习心得

- 判断后端"厚薄"看业务逻辑和状态存在哪；"薄后端+富前端"只是 Serverless 那一代的风格，前后端分离才是当下事实标准
- AI 应用的特征是"请求少但每次等待极长"，恰好命中 async 的主场——FastAPI 成为 AI 应用 Web 层事实标准（vLLM/Ollama/LangServe 全基于它）不是偶然
- 概念打架时往精确规则退一步：不是"async 只能干快活"，而是"async 里只能 await 不能傻等"——快慢是表象，等的方式才是本质
