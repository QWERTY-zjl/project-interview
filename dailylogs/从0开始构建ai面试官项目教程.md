# 从0开始构建ai面试官项目教程

## 前言

本人只是一个本科ai应用开发初学者，本项目的所有做法只是基于我的个人经验，可能 not the best practice。所以在本教程只起到抛砖引玉的作用，希望大家能设计出更优的解决方案。

## 构建虚拟环境 venv

对于实际的开发环境，市场上的软件依赖环境千变万化，我们不可能用一种版本就可以满足任何项目的开发，所以需要使用虚拟环境来隔离不同的项目依赖，避免不同项目之间"串"了。

**1. 创建虚拟环境**

`venv` 是 Python 3.3+ 的内置模块，无需额外安装。注意：要先确认项目依赖支持的 Python 版本（例如 mineru 要求 `>=3.10,<3.14`），再用对应版本创建：

```powershell
py -3.13 -m venv venv
```

**2. 激活虚拟环境**

```powershell
venv\Scripts\activate
```

激活后，本项目所有的依赖都会安装在这个虚拟环境中。

**3. 安装项目依赖**

```powershell
pip install -r requirements.txt
```

`requirements.txt` 里记录了项目的所有依赖及版本号。国内网络建议加上镜像加速：

```powershell
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

## 分析项目需求

这是一个ai面试官项目，首当其冲需要ai来充当面试官的任务。对于ai的调用有本地部署和调其他厂商的api两种方式。对于一个买不起算力的穷b，只能调别人的api，当然有服务器的也可以尝试本地部署一个LLM。除了ai，我们还需要一个数据库来存储用户信息、面试问题等。对于初学者来说，建议使用mysql来存储数据。除此之外还有前端网页设计和后端api接口设计，这部分对于如今的agent来说已经非常容易了，可以交给ai来做，这里我选择trae这个ai IDE来辅助项目的构建。对于前端的网页设计，可以交给豆包之类的先让他们生成各个部分的图片再丢给trae，或者给出别人的好的网页让trae复刻即可，再让trae根据前端设计后端接口，做前后端对接和网页实际运行往往bug很多，大家选择能力比较强的LLM（GLM之类的），别觉得贵，你用弱的模型可能反功半年都不一定找得出来，到时候token花费还要更多。

所以，这个项目的整体需求是：

1. **前端**：负责用户交互，展示项目功能。
2. **后端**：负责处理用户请求，与数据库交互。
3. **数据库**：负责存储项目数据。
4. **ai**：负责面试官的任务，包括生成面试问题、解析简历、与用户交互等。

## ai服务模块

### 1. 面试问题生成服务模块

这个模块负责根据用户的简历，调用ai模型生成面试问题。

整体流程是：

1. 接收用户的简历。
2. 调用ai模型根据用户的简历生成面试问题。
3. 返回生成的面试问题给用户。

要注意的是：我们上传的简历一般不是文本格式，而更有可能是pdf的格式，所以我们要设计将pdf格式转换成文本格式的功能。有三种方法：

1. **多模态大模型直接解析**：调用的大模型本身具有多模态能力，直接上传文件即可解析出文本内容。当然像我这种穷逼肯定不可能用这种方法。
2. **PyPDF2 解析**：有没有什么更省钱的方法？有的兄弟有的。使用 PyPDF2 来解析pdf文件，将pdf文件转换为文本格式。这是python的一个扩展库，可以解析pdf中的纯文本内容，把解析出来的内容丢给大模型即可。
3. **mineru 本地部署**：还有一种更超模的做法——mineru，这个东西我在之前的文章介绍过，把它本地部署下来解析也行。虽然一般简历只有文本内容，在本项目中体现不出优势，但是在智能客服项目中pdf可能包含图片、表格等，需要解析出这些内容。你可以在做这个项目的时候顺便练一下手，之后做这种多模态就更得心应手。

不同的用户需要的是不同的岗位，所以我们需要自己设计prompt，让ai来扮演不同的角色，这样生成的问题更具专业性。该函数需要包含面试简历和角色设定两个传参。并且我们的项目要具有鲁棒性，当调用大模型出现问题时，能够输出备用的面试问题。
