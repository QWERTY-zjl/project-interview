# 提示词工程学习笔记

> 记录提示词工程（Prompt Engineering）的核心概念，并以本项目「出题跑偏」的真实踩坑案例作为直观体现。

## 一、什么是提示词工程

提示词工程 = 通过设计发给大模型的输入文本（提示词），让模型稳定输出符合预期的结果。

大模型没有"逻辑判断"只有"文本接龙"——它输出什么，几乎完全由提示词决定。同一个模型，提示词差一点，结果差很远。所以提示词本身就是一种"编程"：自然语言就是代码。

## 二、一条提示词的结构要素（对照本项目 prompt.py）

本项目所有 AI 调用的提示词都遵循同一个结构（见 [prompt.py](../app/ai_services/prompt.py) 的 `build_interview_prompt`）：

| 要素 | 作用 | 项目中的位置 |
|---|---|---|
| 角色设定 | 给模型一个身份，约束专业度和语气 | "你是一位资深的XX岗位面试官"（system 消息） |
| 素材 | 本次任务的具体原料 | 候选人信息 / 应聘职位 / 简历分析结果（user 消息） |
| 输出格式约束 | 规定返回结构，程序才能解析 | "必须以 JSON 格式返回，结构为 {...}" |
| 指令 | 明确要做什么、做多少、按什么标准 | "生成 5 个问题，每个含评分标准" |

**最容易出问题的就是"素材的权重"**——素材都给了，但没告诉模型哪个重要、哪个次要，模型自己挑一个抓着不放。

## 三、项目踩坑实录：AI 应用经理的简历，出的是前端题

### 现象

上传 AI 应用经理的简历，生成的 5 道面试题全是前端问题，简历内容被完全无视。

### 排查：一个坑，三层

出题方向由「目标岗位」驱动，而岗位字段从页面到提示词的路上有三层问题，任何一层都可能让出题跑偏：

```text
第 1 层（前端默认值）  admin.html 里 targetPosition: 'frontend'
                      用户没填岗位时，这个字面量被原样传给后端

第 2 层（后端兜底）    resume_api.py: "name": target_position or "前端开发"
                      岗位为空串时，硬编码兜底成"前端开发"

第 3 层（提示词无权重）prompt.py 旧指令只说"根据以上信息生成 5 个问题"
                      岗位名和简历内容平铺在一起，没有优先级
```

第 3 层还有一个隐藏放大器：个人版没有岗位库，「岗位要求/岗位职责」两个字段**永远是"未提供"**——模型手里其实只有岗位名 + 简历两样素材，旧指令让它自己挑，它抓着岗位名泛泛出题，简历被完全晾在一边。

### 修复：前端拦截 + 后端校验 + 权重重构

1. **默认值清空**（admin.html）：`targetPosition: 'frontend'` → `''`——默认值是"看不见的输入"，比空值更危险，因为它绕过所有"没填"的校验
2. **前端校验**（admin.html）：提交前检查岗位非空，没填弹窗提示
3. **后端校验**（resume_api.py）：422 拦截 + 明确错误信息，防绕过前端直接调接口
4. **提示词权重重构**（prompt.py）：给素材标注主次 + 指令编号排优先级：

```text
1. 简历分析结果 = 出题核心依据（围绕真实项目经历、技术栈提问）
2. 应聘职位 = 只定方向和专业边界
3. 简历与岗位不一致时 → 以简历为主，加 1 个方向/动机题
4. 禁止出与两者都无关的泛概念题
```

同时在素材区直接标注：`简历分析结果（出题的核心依据）`、`应聘职位...（仅供方向参考）`——让模型第一眼就看清主次。

### 教训总结

- **提示词里的每份素材都要有明确权重**，别让模型自己决定听谁的
- **"未提供"的字段要处理**：要么不进提示词，要么明确说它仅供参考，否则模型会对着空素材自由发挥
- **默认值是隐形输入**：前端默认值会绕过"必填"校验直接进业务链路
- **必填校验要做两层**：前端管体验（弹窗提示），后端管兜底（防绕过）

## 四、本项目用到的其他提示词技巧

| 技巧 | 项目中的例子 | 目的 |
|---|---|---|
| JSON 输出约束 | system 里直接写 `{"questions": [...]}` 结构 | 返回可被 `json.loads` 解析，程序可靠处理 |
| 兜底占位符 | `position.get('name', '未提供')` | 防止提示词里出现空白/None 导致模型困惑或报错 |
| 围栏剥除兜底 | report_service 收到 \`\`\`json 围栏时剥掉再解析 | 模型不守格式约束时的二次容错 |
| 数量上限对齐 | 提示词要 5 题 ↔ 代码 `valid[:5]` 截断 | 提示词约定和程序校验必须一致 |
| 评分标准前置 | 出题时生成 score_standard，报告时回传给模型 | 同一把尺子打分，评分才有依据 |

## 五、术语速查表

| 术语 | 含义 |
|---|---|
| Prompt | 发给大模型的输入文本 |
| System / User 消息 | 系统消息定角色和规则；用户消息给素材和任务 |
| Token | 模型计费和长度单位，约 0.5~1.5 个汉字 |
| 幻觉 | 模型一本正经编造不存在的内容，素材权重不清时易发生 |
| temperature | 采样随机度：出题可以稍高（多样），评分抽取应较低（稳定） |
