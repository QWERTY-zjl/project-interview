# 数据库学习笔记：SQLite / SQL / ER 图 / 连接池 / 工具

> 数据库主题参考笔记，涵盖数据库本体、操作语言、表结构设计、连接管理与工具生态

## 一、SQLite

### 1.1 是什么

**嵌入式单文件数据库**：没有服务端进程，整个数据库就是一个文件，程序直接读写这个文件。Python 标准库 `sqlite3` 零配置可用。

### 1.2 对比 MySQL

| | SQLite | MySQL |
|---|---|---|
| 架构 | 无服务端，直接操作文件 | 客户端-服务端 |
| 并发管理 | 文件锁，粗粒度 | 服务端调度（行级锁、MVCC） |
| 连接方式 | 打开文件即可（无主机/端口/密码） | 需要地址、账号密码 |
| 适合 | 单机、学习、小工具、移动端 | 多人访问的 Web 服务 |

两者同为关系型数据库、都用 SQL，但**没有亲缘关系**，只是定位不同。

### 1.3 并发与锁

```
多进程同时读：  ✅ 可以（共享读锁）
写：            ⚠️ 全库独占 —— 同一时刻要么"多个读者"，要么"一个写者"
```

- 报错 `database is locked` = 有别的连接占着写锁/挂着事务，默认等 5 秒超时
- 排查思路：检查还有哪些程序开着这个库（GUI 工具、后端服务），关掉再试
- 升级方案：`PRAGMA journal_mode=WAL;` 让"读写不互斥"，执行一次持久生效

### 1.4 元数据与表结构

- 每个库自带"目录表" `sqlite_master`，存着所有表的定义：`SELECT type, sql FROM sqlite_master`
- GUI 工具的"定义/DDL"标签、自动 ER 图，底层就是查这些元数据画出来的
- SQLite **默认不强制外键约束**：建表语句里写 FOREIGN KEY 主要用于文档说明和工具画线，数据一致性靠应用层保证

## 二、SQL 常用语句

### 2.1 什么是 SQL

**SQL**（Structured Query Language，结构化查询语言）：和关系型数据库打交道的专用语言。程序自己不会"摸"数据库文件，而是把 SQL 语句通过驱动发给数据库执行。MySQL、SQLite、PostgreSQL 都说 SQL，差别只在方言细节。

按用途分两大类（项目建表脚本里两类都出现了）：

| 分类 | 全称 | 干什么 | 动的是 | 项目里的语句 |
|---|---|---|---|---|
| **DDL** | Data Definition Language | 定义/修改表结构 | 表格骨架 | CREATE TABLE、ALTER TABLE |
| **DML** | Data Manipulation Language | 增删改查数据 | 表格里的内容 | INSERT、SELECT、UPDATE、DELETE |

记忆口诀：**DDL 动骨架，DML 动内容**。

### 2.2 CREATE TABLE —— 建表（DDL）

```
CREATE TABLE IF NOT EXISTS 表名 (
    字段名  数据类型  [约束],
    ...
)
```

项目实例（users 表简化版，完整版见建表脚本）：

```sql
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 主键，自增编号
    username TEXT NOT NULL,                 -- 必填文本
    created_at INTEGER DEFAULT (strftime('%s', 'now'))  -- 默认当前Unix时间戳
)
```

| 关键词 | 作用 |
|---|---|
| IF NOT EXISTS | 表已存在就跳过不报错 → 脚本可以放心重复执行（幂等） |
| PRIMARY KEY | 主键：本表的唯一编号，永不重复 |
| AUTOINCREMENT | 自增：插入时不用填 id，数据库自动取上一行 +1 |
| NOT NULL | 非空约束：这列必填，不填报错 |
| DEFAULT 值 | 默认值：插入时没给就自动填 |

SQLite 四种常用数据类型：**INTEGER**（整数）、**TEXT**（文本）、**REAL**（小数）、**BLOB**（二进制文件，如录音、PDF）。

### 2.3 INSERT —— 插数据（DML）

```
INSERT INTO 表名 (列1, 列2, ...) VALUES (值1, 值2, ...)
```

项目里的两个细节（都出自建表脚本）：

```sql
-- ① OR IGNORE：撞车（如唯一字段重复）就跳过不报错 → 脚本重复执行不会插重
INSERT OR IGNORE INTO interview_types (name, description) VALUES ('前端开发面试', '...');

-- ② ? 占位符：值不拼进 SQL 字符串，而是作为参数单独传入
cursor.execute("INSERT INTO pricing_plans (...) VALUES (?, ?, ?)", plan)
```

`?` 占位符两大好处：**① 值和 SQL 代码分离，防 SQL 注入**（用户输入的内容不会被当成 SQL 语法执行）**② 一段 SQL 配不同参数反复用**（6 档套餐共用一条语句）。

### 2.4 SELECT —— 查数据（DML）

```
SELECT 列1, 列2 FROM 表名 [WHERE 条件] [LIMIT 行数]
```

项目实例：

```sql
-- 迁移段的"探测"：只取 1 行；查得动 = 字段存在，报 no such column = 缺字段
SELECT user_score FROM interview_questions LIMIT 1;

-- 查表结构（SQLite 特有，验证字段是否补齐时用过）
PRAGMA table_info(users);
```

Python 侧取结果：`cursor.fetchall()` 取全部行、`fetchone()` 取一行；连接设置了 `row_factory = sqlite3.Row` 后可以用 `row["列名"]` 按列名取值（否则只能按下标 `row[0]`）。

### 2.5 UPDATE / DELETE —— 改与删（DML）

```
UPDATE 表名 SET 列 = 新值 WHERE 条件
DELETE FROM 表名 WHERE 条件
```

项目场景：登录成功后更新 `UPDATE users SET last_login_at = ? WHERE id = ?`；购买/使用后扣配额 `UPDATE user_quotas SET ... WHERE user_id = ?`。

> ⚠️ UPDATE / DELETE 忘写 WHERE = 整张表全改/全删，是新手代价最高的事故。

### 2.6 ALTER TABLE —— 给已存在的表加列（DDL）

```
ALTER TABLE 表名 ADD COLUMN 字段名 类型
```

只用于**已经建好的表**（新建表直接在 CREATE 里写全）。旧数据的新列自动填 NULL 或默认值，不破坏原有数据。

项目迁移段用它做「探测式迁移」：`SELECT 字段 LIMIT 1` 试探 → 报 `no such column` 就 ALTER 补列 → commit，四步一个 try/except 块。详见建表脚本的迁移段注释。

### 2.7 commit —— 事务的保存键

数据库的修改默认先放在"暂存区"（事务），`conn.commit()` 后才真正写入 .db 文件——类比编辑文档必须 Ctrl+S 才保存。

- 不 commit 就退出 = 改动作废
- 一直不 commit 会让连接长时间持有写锁，其他连接报 `database is locked`

## 三、ER 图（实体-关系图）

### 3.1 是什么

ER 图（Entity-Relationship Diagram）用来描述数据库设计：有哪些**表**（实体）、每张表有哪些**字段**（属性）、表和表之间怎么**关联**（关系）。是设计数据库和读懂他人设计的通用语言。

### 3.2 方块 = 表

```
users {
    INTEGER id PK      ← 主键（Primary Key）：这张表的"身份证号"，唯一不重复
    INTEGER user_id FK ← 外键（Foreign Key）：存的是别的表的主键，用来"指向"那张表
    TEXT username      ← 普通字段
}
```

读表诀窍：**先找 PK（我是谁），再找 FK（我属于谁）**——表与表的连线就落在 FK 字段上。

### 3.3 连线 = 关系（鸦爪记号 Crow's Foot）

```
users ||--o{ interviews : "user_id"
读作：一个用户可以有 0~N 场面试；每场面试必须属于恰好 1 个用户
```

| 符号 | 含义 | 渲染后长什么样 |
|---|---|---|
| `\|\|` | 恰好 1 个 | 两横杠，像"=" |
| `o{` | 0 到 N 个 | 圆圈 + 鸦爪（三叉） |
| `\|{` | 1 到 N 个 | 鸦爪（无圆圈） |
| `o\|` | 0 或 1 个 | 圆圈 + 横杠 |

口诀：**数横杠定"一"，看分叉定"多"，见圆圈加"可以没有"**；连线上的标签 = 关联用的外键字段名。

### 3.4 读图三步法

1. 找**没有 FK 的"根表"**（通常是 users、分类表这类基础数据）
2. 看 **FK 最多的表**（往往是业务枢纽，如订单、记录表）
3. 顺着每条线**念成中文句子**，用业务常识检验合理性

常见结构：漏斗收窄（宏观 → 细节）；一张表有多个 FK = 同时属于多个维度（交叉记录）。

### 3.5 画图工具对比

| 工具 | 方式 | 适用场景 |
|---|---|---|
| Navicat / DBeaver「逆向数据库到模型」 | 连上真库自动生成 | 看现有库的结构（最常用） |
| Mermaid | 纯文本写在 Markdown 里 | 文档/README，git 能 diff，AI 好生成 |
| draw.io | 手动画，存文件 | 架构图、自由排版 |
| PowerDesigner / PDManer | 正式设计文档 | 传统企业（银行、国企） |

### 3.6 求职视角

能力层次：**ER 设计思想 > 读图能力 > 某个工具的语法**。面试考的是"给一个业务场景设计几张表、什么关系"，白板画鸦爪记号是通用语言；Mermaid 只是载体，会读会改即可。

## 四、数据库连接管理与连接池

当你建立起一个数据库和软件配套运行时，软件在明面上运行，数据库在背地里修改，他们并行不悖是依靠什么呢？答案是连接。

### 什么是连接？

**连接**（Connection）是指软件与数据库之间的通信通道，用于执行 SQL 语句和接收结果。就是软件修改了某个信息时，软件会通过连接向数据库发送 SQL 语句，数据库会执行语句修改数据库种相应的表。

### 是谁在申请连接？

不是软件不是用户而是代码执行到某个数据库操作时执行的，所以申请连接的是一个操作，每次修改数据库时都需要申请一个连接，该对象类似于文件的句柄——拿到它才能对数据库执行 SQL，连接关闭后就无法再操作了。

### 连接管理

你的软件给很多人在用，那么数据库的连接并修改就会很频繁，对连接的管理至关重要，连接管理包括连接的创建、维护、关闭等操作。

### 最朴素的做法

> 下方代码块与 `app/db/db.py` 当前版本一致（2026-09-29 同步）。

```
"""数据库模块

作用：整个项目所有需要读写 SQLite 数据库的代码，都通过这里拿连接/还连接。
相当于数据库的「统一入口」，其他模块不直接 import sqlite3。
"""

import sqlite3          # Python 自带的 SQLite 驱动，标准库，不用安装
import logging
from app.config.config import DATABASE_NAME  # 从配置文件读取数据库文件路径

# logging.getLogger(__name__)：拿到本模块专属的日志记录器，
# 打日志时会自动带上模块名（如 app.db.db），方便排查是哪个文件输出的
logger = logging.getLogger(__name__)

# 全局连接池，用于管理所有活跃的数据库连接
# 本质就是一个普通 Python 列表，记录当前「借出去还没还」的连接对象。
# 作用：程序退出时能统一关闭所有连接，避免数据库文件被占用。
# 注意：SQLite 本身不支持真正的多线程连接池，这里只是简易登记。
_connections = []

def get_db():
    """获取数据库连接

    谁要用数据库，谁就调这个函数「借」一个连接。
    用完后必须调 return_db(conn) 还回去。

    Returns:
        sqlite3.Connection: 配置了行工厂的数据库连接对象
    """
    # 连接数据库文件（DATABASE_NAME 在 config.py 里已用 __file__ 锚定为
    # app/db/interview_system.db 的绝对路径，不随启动目录变化）。
    # 如果文件不存在，SQLite 会自动创建一个空的 .db 文件
    conn = sqlite3.connect(DATABASE_NAME)
    # row_factory = sqlite3.Row：设置「行工厂」。
    # 默认查出来的每行是元组 (值1, 值2)，只能按下标取 row[0]；
    # 换成 Row 后可以像字典一样用列名取：row["user_id"]、row.keys()。
    # 这是本项目所有查询都能写 row["列名"] 的原因
    conn.row_factory = sqlite3.Row  # 支持列名访问
    # 登记到全局列表，表示这个连接已借出、尚未关闭
    _connections.append(conn)
    return conn

def return_db(conn):
    """关闭数据库连接并从连接池移除

    「还连接」：用完必须关掉，否则连接一直占着数据库文件（Windows 上
    表现为 .db 文件被锁定，其他工具打开会报 database is locked）。

    Args:
        conn: 数据库连接对象
    """
    # 两个判断：conn 不是 None，且确实是之前借出去的（在列表里登记过），
    # 防止重复关闭或关掉别人的连接
    if conn and conn in _connections:
        conn.close()            # 真正关闭与数据库文件的连接
        _connections.remove(conn)  # 从登记列表中移除

def init_db():
    """初始化数据库（创建表结构）

    程序启动时由 server.py 调用一次。
    【原理】import 一个模块时，Python 会把模块顶层的代码从头到尾执行一遍——
    建表脚本正是利用这一点：import 它 = 执行建库建表 + 探测式补字段 + 插默认数据。
    脚本内部用 IF NOT EXISTS / try-except 迁移保证重复执行也安全（幂等），
    新建库和老库两种情况都覆盖，所以这里不需要先判断文件存不存在。

    【import 路径】import 后面写「点分路径」= 文件在项目里的目录位置：
    app/db/create_personal_interview_system_db.py → app.db.create_personal_interview_system_db
    """
    import app.db.create_personal_interview_system_db

def close_all_connections():
    """关闭所有数据库连接（程序退出时调用）"""
    # _connections[:] 是浅拷贝：先复制一份再遍历删除。
    # 如果直接遍历 _connections 边遍历边 remove，列表长度变化会导致
    # 漏删或跳过元素，这是 Python 列表遍历删除的经典坑。
    for conn in _connections[:]:  # 使用副本避免迭代时修改
        try:
            conn.close()
            _connections.remove(conn)
        except Exception as e:
            # 单个连接关闭失败只记日志，不影响其他连接继续关闭
            logger.error(f"[DB] 关闭连接失败: {e}")

```

注意：这里的列表**只是登记簿，不是池子**——`get_db()` 每次都是**新建**一个连接并登记，`return_db()` 直接关闭并移除，连接不复用。列表的真正用途只有一个：程序退出时能按名单统一关闭所有还开着的连接。另一种复用思路见下一节 db_pool.py（受 SQLite 线程约束，最终形态是"线程本地"复用，见踩坑小节）。

### 路径锚定：为什么 DATABASE_NAME 不能写裸文件名

`"interview_system.db"` 这种裸文件名是**相对路径**，跟着进程的启动目录走：从仓库根启动就连 `<仓库根>/interview_system.db`，从别处启动又是另一个文件——曾经实际造成"服务器连到一个凭空生成的空库，所有查询报 no such table"。

解法是在 config.py 里用 `__file__` 把路径**锚定**为绝对路径：

```
DATABASE_NAME = os.path.join(os.path.dirname(os.path.dirname(__file__)), 'db', 'interview_system.db')
```

`__file__` = config.py 自己的路径 → 取两次 dirname 到 app/ → 再拼上 `db/interview_system.db`。不管从哪个目录启动，连的都是同一个库文件（建表脚本用的同一招）。

### 连接池

最朴素的做法每次建立连接关闭连接都是需要耗时的，本地项目还好，一旦项目是真实上线的，访问的不是本地数据库文件了，就涉及网络传播的问题（建立TCP 连接 + 密码认证防止网络传输泄密 + ），延时会大大增加，于是就有了连接池的概念。

### 什么是连接池？

可以理解为**缓存**——缓存的对象不是数据，而是"连接"本身：程序启动时预先建立好一批连接放进池子，要用就借、用完就还，连接在池子里反复复用，而不是反复新建/销毁。目的是省掉每次建立、断开连接的固定开销（"建连税"）。

对 SQLite 这种本地文件库，建连只是打开一个文件，开销很小；一旦换成 MySQL 等网络数据库，每次建连要 TCP 握手 + 密码认证，毫秒级开销 × 高并发访问，连接池就从"可选"变成"标配"。

### 踩坑：预建池违反 SQLite 线程安全

连接池的经典实现是"启动时预建 N 个连接，谁要用就借给谁"。但 sqlite3 默认 `check_same_thread=True`：**一个连接只能被创建它的那个线程使用**。主线程预建的连接借给其他线程，直接抛 `ProgrammingError: SQLite objects created in a thread can only be used in that same thread`。

解法是改用「线程本地」策略：每个线程第一次用时**现场**建一个连接，存进 `threading.local()`（每个线程看到各自独立的存储空间），之后该线程一直复用自己那个，跨线程互不共享。

### 与最朴素的做法的区别

| | 朴素做法（db.py） | 线程本地模式（db_pool.py） |
|---|---|---|
| 借连接 | 每次新建一个 | 本线程首次用时现场建，之后复用 |
| 还连接 | `close()` 真关闭 | 无需归还（连接常驻），`return_connection` 保留为空操作 |
| 连接生命周期 | 一次操作一个连接 | 线程活多久，连接活多久 |
| 为什么不能预建 N 个分发 | — | `check_same_thread=True` 禁止跨线程使用连接 |
| 适用场景 | SQLite 本地文件（建连便宜） | 多线程服务想让每线程免掉重复建连 |

### 实现

> 下方代码块与 `app/db/db_pool.py` 当前版本一致（2026-09-29 同步）。该模块目前未被任何代码引用，是备用练习实现。

```
"""
数据库连接池模块
================
线程安全的数据库连接池（按线程隔离）

和 db.py 的区别：
- db.py 每次操作都新建连接、用完关闭（建连开销小，适合 SQLite）
- 这里每个线程第一次使用时建一个连接，之后该线程一直复用自己的这个

线程安全说明（为什么不能预建 N 个连接来回分发）：
- sqlite3 默认 check_same_thread=True：连接只能被创建它的线程使用
- 预先在主线程建好 pool_size 个连接再借给其他线程，会直接抛
  ProgrammingError: SQLite objects created in a thread can only be
  used in that same thread
- 因此采用「线程本地」策略：按需创建 + 线程内复用，跨线程互不共享
"""

import threading
import sqlite3
from sqlite3 import Connection          # 连接对象的类型，只用于类型注解
from app.config.config import DATABASE_NAME


class DatabasePool:
    """
    线程安全的数据库连接池（每线程一个连接）
    """

    def __init__(self, db_name: str):
        """
        参数:
            db_name: 数据库文件名
        """
        self.db_name = db_name
        # threading.local()：每个线程看到的是各自独立的存储空间，
        # 线程 A 写入的 self._local.conn，线程 B 读不到——隔离的关键
        self._local = threading.local()
        # 登记所有线程创建过的连接，供程序退出时统一关闭
        self._all_connections: list[Connection] = []
        self._lock = threading.Lock()      # 保护登记列表的并发修改

    def get_connection(self) -> Connection:
        """
        获取当前线程专属的连接，第一次调用时现场创建

        返回:
            数据库连接对象（永远成功，不会再返回 None）
        """
        conn = getattr(self._local, "conn", None)
        if conn is None:                    # 本线程还没建过连接
            conn = sqlite3.connect(self.db_name)
            conn.row_factory = sqlite3.Row  # 同 db.py：让查询结果支持按列名取值
            self._local.conn = conn         # 存进线程本地，下次同线程直接复用
            with self._lock:                # 登记时要加锁（多线程可能同时登记）
                self._all_connections.append(conn)
        return conn

    def return_connection(self, conn: Connection):
        """
        将连接返回连接池

        线程本地模式下连接常驻复用，无需真正归还。
        保留此方法是为了兼容旧的调用习惯（借了还，不报错）。
        """
        pass

    def close_all(self):
        """
        关闭所有线程创建的连接

        程序退出时调用。注意：sqlite3 不允许跨线程 close，
        所以这里只能关掉登记列表里能关的连接，
        其他线程创建的连接会报 ProgrammingError 并被捕获记录，
        程序退出时进程结束，连接随进程释放，不影响数据安全。
        """
        with self._lock:
            for conn in self._all_connections:
                try:
                    conn.close()
                except Exception as e:
                    print(f"[ERROR] 关闭数据库连接失败: {e}")
            self._all_connections.clear()


# 创建数据库连接池实例
# 模块级别直接实例化（全局单例用法）；不再预建连接，各线程首次使用时才建
db_pool = DatabasePool(DATABASE_NAME)

```

### 小结

- **连接** = 打开的数据库会话（对 SQLite 就是一个打开的文件句柄 + 内存状态），不是表，也不是进程
- **连接池** = 连接的缓存，用复用代替反复建/关；经典"预建池"在 SQLite 里行不通（线程约束），落地形态是"线程本地复用"
- **路径锚定** = 数据库文件路径必须用 `__file__` 固定为绝对路径，否则跟着启动目录走，会出现"连到凭空生成的空库"这种隐蔽故障
- 本项目（SQLite + Flask 单机）朴素模式足够，实际全部使用 db.py；db_pool.py 是备用练习实现，尚未接入任何模块
- 面试考点：为什么用连接池？——复用昂贵的建连开销，避免频繁建立/断开的性能浪费，同时限制总连接数；追问 SQLite 里的坑 → check_same_thread 线程约束

### 5.2 CLI vs GUI

- **CLI**（Command Line Interface，命令行界面）：在终端敲命令操作，如 `git`、`uv`、`python`
- **GUI**（Graphical User Interface，图形界面）：点按钮操作，如 Navicat、DBCode 面板
- 底层能力相同；CLI 快、可写脚本自动化、能被其他程序调用；GUI 直观、适合浏览查看
- 命名规律："xxx CLI" = xxx 的命令行版

### 5.3 Node.js（部分插件 CLI 的依赖）

- **让 JavaScript 脱离浏览器直接在操作系统上运行**的运行时，相当于 JavaScript 的"python.exe"
- `npm` 是它的包管理器（对应 Python 的 pip/uv）
- 前端开发（Vue/React）必需；很多编辑器插件的后台进程也是 Node 写的，报 `Node.js was not found on PATH` 即缺它
- 安装：`winget install OpenJS.NodeJS.LTS`

### 5.5 WAL 模式与配套文件（-wal / -shm）

之前说"长期方案是开 WAL，现阶段暂不动"——现在有工具替你开了：DBCode 的驱动连库时会自动执行 `journal_mode=WAL`，以 WAL 模式打开库。此时库文件旁会出现两个配套文件：

| 文件 | 作用 |
|---|---|
| `interview_system.db-wal` | **预写日志**：新写入先追加到这里，空闲时再批量合并回主库（checkpoint 检查点），读写不再互斥 |
| `interview_system.db-shm` | **共享内存索引**：多个进程读 WAL 时用来协调 |

对比默认模式（直接写主库，只出现 `-journal` 锁文件），WAL 把"写"变成先记日志，别人读主库不受影响——正是之前撞锁问题的官方解法。

**什么时候出现 / 消失**

- 出现：任何程序第一次以 WAL 模式打开库的瞬间。WAL 是持久设置（写进库文件头部），之后每次打开都伴随这两个文件
- 消失：最后一个连接正常关闭时，SQLite 会自动把 WAL 合并回主库并删除这两个文件。还能看到它们 = DBCode 还连着（或上次没干净关闭）
